## 1. 概述與願景 (Overview & Vision)

打造一套全自動、100% 免費、零伺服器維護成本的台美雙市場量化選股與機構風控系統。
每日盤後自動抓取數據，執行文藝復興多因子 (0-100) 打分與大摩 2 倍 ATR 風報比計算，結合 Gemini API Key 池審查與興登堡做空一票否決，於隔晨 08:00 前產出「黃金 Top 20」標的，並透過 Telegram 與 GitHub Pages 雙通道交付。

---

## 2. 目標與非目標 (Goals & Non-Goals)

### 目標 (Goals)
1. **全自動定時排程**：每日台股盤後（台灣時間 16:17）與美股盤後（台灣時間 05:23）透過 GitHub Actions 自動觸發。
2. **0-100 分量化評分與風報比約束**：每檔推薦股票必須提供客觀 0-100 分評級，且風報比 (RRR) 嚴格 $\ge 2.0$。
3. **AI 機構審查與興登堡做空否決**：調用 Gemini 免費 API Key 池，自動剔除財報造假、暴雷或財報前夕跳空標的。
4. **雙通道交付**：每日清晨 08:00 前發送 Telegram 摘要推播卡 (<4000字)，並更新 GitHub Pages 現代深色儀表板。
5. **防過度工程化與防封號**：無狀態 (Stateless)、無自建資料庫、無無窮遞迴 commit、運行時間 < 4 分鐘/次。

### 非目標 (Non-Goals - 明確不做)
1. **不做自動下單交易機**：本系統僅提供客觀數據與決策研報，嚴禁自動串接券商 API 下單。
2. **不做高頻交易 (HFT) 或即時日內盤中監控**：僅聚焦每日收盤後的波段選股。
3. **不做複雜的跨日虛擬持倉狀態機**：每日輸出最新客觀排名，避免代碼臃腫。
4. **不做付費期權鏈即時抓取**：美股跳空風險以 arnings_date <= 5天 打標籤預警，零額外 API 成本。

## 3. 使用者故事 (User Stories)

* **US-1**：作為一名波段投資者，我希望在每天早上 8:00 前收到今日精選的 20 檔股票，每檔都有清晰的 0-100 分數與停損停利點位，讓我能在開盤前 10 分鐘做好掛單準備。
* **US-2**：作為一名風險厭惡交易者，我希望每檔推薦標的的風報比都大於 2.0，且已經通過興登堡做空審查，確保我不會買進即將暴雷或被市場主力倒貨的陷阱股。
* **US-3**：作為一名個人開發者，我希望整個系統 100% 運行在 GitHub 免費額度內，免開個人電腦、零主機月租費、且絕對不會因為濫用被封號。

## 4. 系統邊界與功能性需求 (Functional Requirements)

### FR-1：母池管理與除權息復權抓取
- **FR-1.1 (台股母池)**：臺灣 50 + 中型 100 為核心，初篩條件：收盤價 > 10 元，近 20 日均成交額 > 5,000 萬元台幣。
- **FR-1.2 (美股母池)**：S&P 500 + Nasdaq 100 為核心，初篩條件：收盤價 > 5 美元，近 20 日均成交額 > 1,500 萬美元。
- **FR-1.3 (復權還原)**：數據抓取一律啟用 uto_adjust=True，杜絕除權息與拆股導致的均線假跳空。
- **FR-1.4 (休市日阻斷)**：若最新交易日數據已處理過，系統立即退出 (xit(0))，不重複發布。

### FR-2：大盤宏觀溫度計
- 計算加權指數 (^TWII) 與標普 500 (^GSPC) 的現價與 MA60（季線）。
- 若現價 < MA60，整體市場狀態標註為 BEARISH_DEFENSIVE (空頭防守)，推播與儀表板強制置頂警報。

### FR-3：軌道一 - 文藝復興多因子與大摩風報比
- **FR-3.1 (多因子評分)**：
  - 價值因子 (30%): PE/PB 水位、FCF 現金流收益率
  - 品質因子 (25%): ROE、毛利率穩定度
  - 動能因子 (20%): MA20/50/200 多頭排列、RSI(14) 突破強度
  - 市場特色 (25%): 近期營收動能、相對大盤強度
  - 產出標準化 0-100 總分。
- **FR-3.2 (大摩風報比計算)**：
  - 停損價 (Stop Loss) = $	ext{現價} - 2 	imes 	ext{ATR(14)}$
  - 目標價 (Take Profit) = $	ext{現價} + 2 	imes (	ext{現價} - 	ext{停損價})$
  - 風報比 (RRR) =  / (	ext{現價} - 	ext{停損價}) \equiv 2.0$。
  - 倉位建議：計算 1% 本金風險下建議買進股數/張數（向下截斷至整張）。

### FR-4：軌道二 - Gemini API Key 池機構審查與興登堡做空
- **FR-4.1 (API Key 池輪詢)**：讀取環境變數 GEMINI_API_KEYS（逗號分隔），每次調用自動 Round-Robin，遇 429 自動切換下一個 Key。
- **FR-4.2 (興登堡一票否決)**：針對初篩候選名單，AI 無情審問財務暴雷與造假隱憂，若觸發重大紅旗立即剔除並遞補。
- **FR-4.3 (財報跳空預警)**：若標的財報公佈日 $\le 5$ 天，強制標註 [⚠️ 財報前夕]。

### FR-5：交付管道
- **FR-5.1 (Telegram Bot)**：推播 Markdown 富文本卡片，內容包含：大盤宏觀警報、Top 20 簡表、Top 3 金牌機構點評、GitHub Pages 連結。訊息長度嚴格控制在 3500 字元以內。
- **FR-5.2 (GitHub Pages)**：生成 docs/data/latest_tw.json 與 latest_us.json，並透過響應式 docs/index.html 呈現極簡深色 UI 儀表板。

## 5. 驗收標準 (Acceptance Criteria)

- [ ] **AC-1 (數據還原)**：執行台股與美股日 K 下載時，歷史價格均已包含除權息還原，均線無因除息產生的人為斷崖。
- [ ] **AC-2 (休市跳過)**：在週日或國定假日手動觸發工作流時，日誌顯示「本日非交易日，跳過執行」，無推播且 exit code 0。
- [ ] **AC-3 (風報比達標)**：產出的最終 20 檔標的中，100% 標的的 RRR $\ge 2.0$，且每檔具備明確進場價、停損價、目標價。
- [ ] **AC-4 (Key 池容錯)**：配置 2 個以上 Gemini API Key，當模擬第 1 個 Key 觸發 429 限流時，系統無縫切換至第 2 個 Key 完成審判。
- [ ] **AC-5 (推播長度安全)**：Telegram 推播字串長度 $\le 4000$ 字元，無 HTTP 400 錯誤，手機端排版整齊無跑版。
- [ ] **AC-6 (Actions 零封號風險)**：Workflow 僅監聽 schedule 與 workflow_dispatch，Git Commit 附帶 [skip ci]，單次執行時間 $\le 4$ 分鐘。
