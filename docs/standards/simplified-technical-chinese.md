# 🇹🇼 80% 簡化技術中文規範 (STE-TW 規範)

本規範轉譯自航空與工程領域的 **ASD-STE100 (Simplified Technical English)**，專為**台灣使用者與繁體中文軟體專案**客製化。  
核心目標：**精準、無歧義、短句化、降低閱讀負擔**。

---

## 一、 5 大核心原則

### 1. 嚴格限制句子長度 (字數控制)
* **操作步驟與指令**：每句不得超過 **20 個中文字**。
* **架構說明與描述**：每句不得超過 **25 個中文字**。
* **作法**：遇到長句，立即使用句號拆分為多個獨立短句。

### 2. 單字單意與台灣資訊標準用語
* **單一概念使用單一名稱**：不要混用同義詞。
* **採用台灣資訊工程標準習慣用語**：
  * 使用「**儲存庫**」（非 倉庫 / Repo）
  * 使用「**程式碼**」（非 代碼 / Code）
  * 使用「**資料庫**」（非 數據庫 / DB）
  * 使用「**專案**」（非 項目 / Project）
  * 使用「**伺服器**」（非 服務器 / Server）
  * 使用「**快取**」（非 緩存 / Cache）
  * 使用「**執行緒**」（非 線程 / Thread）
  * 使用「**驗證**」（非 校驗 / 檢核 / 確認）

### 3. 主動語態與動詞開頭 (祈使句)
* 操作步驟必須以**動詞開頭**。
* 嚴格禁止被動語態（避免使用「被」、「由...完成」）。
* **正確**：系統抓取每日盤後交易資料。
* **錯誤**：每日盤後交易資料會被系統自動抓取。

### 4. 嚴禁名詞連續堆疊 (名詞串接上限 3 個)
* 中文容易將過多名詞連綴成串，造成閱讀困難。
* 連續名詞**最多 3 個**；超過者必須拆解為動詞或加助詞。
* **錯誤**：建立文藝復興多因子大摩風報比評分引擎系統。（6 個名詞堆疊）
* **正確**：建立評分引擎，計算多因子分數與風報比。

### 5. 事實為本，杜絕模糊形容詞
* 刪除所有主觀、情緒化與模糊修飾詞（例如：非常、極佳、相當、超快、簡單）。
* 一律改用**客觀數據與可驗證條件**陳述。
* **錯誤**：系統提供極為迅速且高度穩定的推播服務。
* **正確**：系統在 3 秒內完成推播，可用性達 99.9%。

## 二、 撰寫對照範例

| 類別 | 不佳寫法 (冗長、被動、模糊) | STE-TW 規範寫法 (短句、主動、精準) |
| :--- | :--- | :--- |
| **功能說明** | 本系統會自動化地在每天下午盤後時間被觸發，並以極快速度抓取全市場所有台股與美股最新交易資訊。 | 系統在每日盤後觸發。系統抓取台股與美股交易資料。 |
| **操作指引** | 請使用者必須先進行環境變數檔案的檢查確認，確定金鑰無誤之後再啟動背景排程服務。 | 1. 檢查環境變數檔案。<br>2. 確認金鑰內容。<br>3. 啟動背景排程服務。 |
| **架構決策** | 考量到未來維護上的便利性與擴展靈活性，我們決定不採用過度複雜的微服務架構，而選擇單一檔案即可運行的極簡架構。 | 系統採用單一架構。架構不使用微服務。此設計降低維護成本。 |

## 三、 執行守則

本專案中所有下列文件，均必須遵守本規範：
1. 產品需求規格書 (`docs/spec/`)
2. 架構決策紀錄 (`docs/adr/`)
3. 代碼註解與介面說明 (Code Comments & API Specs)
4. 對外發布之使用者手冊與 Telegram 推播訊息
